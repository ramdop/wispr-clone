# Implementation Learnings

## Initial Setup

- Project initialized as a macOS Menubar app.
- Key constraints: No Dock icon (`LSUIElement` = true), Sandboxing considerations for Accessibility API.

## Troubleshooting

- **Swift Concurrency**: `async` keyword is used for function declarations, `await` is for calling them. Typo fixed in `AppState.swift`.
- **Package Structure**: Moved files to `Sources/` to use with Swift Package Manager for lighter weight project definition. `Info.plist` embedding requires linker flags in `Package.swift`.

## AI / LLM Integration

- **Prompt Engineering**: Models like GPT-4o are highly compliant but can be pedantic. If instructed to "format if it looks like a list", they may conversationally refuse inputs that don't match that criteria perfectly.
  - **Fix**: Update prompts to always require a text output, instructing the model to default to simple punctuation correction if no complex structure is detected. Never give the model an "out" to refuse processing.
- **Hallucination Control (Llama 3)**:
  - **Issue**: Faster models like `llama-3.1-8b-instant` are prone to "autocompletion" behavior, inventing plausible next items in a list (e.g., adding "Financial Report" to a list of meeting topics).
  - **Fix**:
    1. Set `temperature` to `0.0` (Deterministic).
    2. Used **XML Tagging Strategy**: Instructed model to wrap valid output in `<formatted_text>` tags.
    3. Implemented regex extractor to capture _only_ the content inside tags, ignoring all preambles/postscripts.

## Cloud Integration

- **Groq Deprecation**: Groq deprecates models aggressively. `llama3-8b-8192` was removed mid-development.
  - **Fix**: Switched to `llama-3.1-8b-instant`.
- **API Key Management**:
  - **Issue**: Sharing a single `apiKey` variable across providers causes 401 errors when switching services.

## UI / UX Refinements

- **HUD Persistence**: Users expect the "Pill" to remain visible while the LLM is thinking, not just disappear into the ether.
  - **Fix**: Updated `AppState` to keep `HUDOverlay` visible during `.transcribing`, `.processing`, and `.pasting` states.
- **Visual Feedback**: A static waveform during processing feels broken.
  - **Fix**: Implemented a conditional view in `WaveformView`:
    - **Recording**: Dynamic Waveform.
- **Clipboard Hygiene**: Direct pasting pollutes the user's clipboard history (e.g., Maccy, Paste).
  - **Fix**: Implemented "Stealth Paste" protocol:
    1. Backup current clipboard.
    2. Write new text with `org.nspasteboard.transient` and `org.nspasteboard.AutoGeneratedType` metadata.
    3. Trigger Paste (Cmd+V).
    4. Restore original clipboard content after 600ms.

## Research: Wispr Flow Architecture

User requested research on how "Wispr Flow" achieves its advanced modes (Context & Translation).

### Core Features & Implementation Hypothesis

1.  **Context Awareness**:
    - **Feature**: Reads the text _surrounding_ the cursor to adapt tone and correct jargon.
    - **Implementation**: Likely uses **Accessibility APIs (`AXUIElement`)** to query `kAXValueAttribute` of the focused text area. Security permissions (Accessibility) are critical here.
    - **Privacy**: Feature is optional/toggleable due to sensitivity of reading screen content.

2.  **Command Mode / Editing**:
    - **Feature**: User highlights text and speaks a command ("Make this friendlier").
    - **Implementation**:
      1.  Detect selection coverage via Accessibility API.
      2.  LLM Prompt: `Input: [Selected Text], Instruction: [Spoken Command]`.
      3.  Replace selection with output.

3.  **Multilingual & Translation**:
    - **Feature**: Auto-detects language (e.g., switching to Spanish mid-sentence) and supports "Translate to English" commands.
    - **Implementation**:
      - **Auto-Detect**: Native feature of Whisper models (`ggml-base.bin` vs `.en.bin`).
        - **Translation**: Whisper has a specific `translate` task token that forces output to English regardless of input language.

### Command Mode Implementation

- **Architecture**:
  - **Dual Hotkeys**: `Option+Space` (Dictation) vs `Control+Option+Space` (Command).
  - **Context Engine**: Uses `AXUIElement` (Accessibility API) to read the user's text selection _before_ recording starts.
  - **Prompting**: Specific `PromptTemplate.command` instructs the LLM to rewrite the _Input Selection_ based on the _Input Instruction_.
- **Privacy**: Context is only read when the specific "Command Mode" hotkey is triggered.

### Troubleshooting: Hotkeys

- **Issue**: Complex hotkeys (e.g., `Control+Option+Space`) often fail to send a clean `kEventHotKeyReleased` event with the correct ID if modifiers are released in a specific order.
  - **Fix 1 (Failed)**: Fail-safe release handler in `HotKey.swift`. Still unreliable for complex chords.
  - **Fix 2 (Failed)**: **Session State Polling**. `combinedSessionState` returned `false` incorrectly, stopping recording immediately.

### Troubleshooting: Command Mode

- **Issue**: If context capture fails (e.g., user selects text in a non-accessible app), the app fell back to standard dictation, destructively overwriting text.
- **Fix**:
  1. **Strict Mode**: If `contextText` is missing in Command Mode, we abort with an error. No more accidental overwrites.
  2. **Attribute Fallback**: `ContextManager` now tries `kAXValueAttribute` (getting the whole field value) if `kAXSelectedTextAttribute` fails. This fixes issues in apps that don't expose fine-grained selection ranges.

## Custom Vocabulary (Dictionary Tab)

- **Feature**: Users can add custom words (names, acronyms, technical terms) to improve speech recognition accuracy.
- **Implementation**:
  - Created `CustomVocabularyStore.swift` for persistence to `custom_vocabulary.json` in Application Support.
  - Created `DictionaryTab.swift` UI for add/remove words.
  - Updated `SpeechTranscriber` protocol to accept `contextualStrings` parameter.
  - `AppleSpeechEngine` passes custom words to `SFSpeechURLRecognitionRequest.contextualStrings`.
- **Files**: `CustomVocabularyStore.swift`, `DictionaryTab.swift`, `SpeechTranscriber.swift`, `MenuBarView.swift`

## Auto-Learn Personal Dictionary (Correction Learning)

- **Feature**: Automatically learns from user corrections after pasting transcription. Promotes corrections to dictionary after 2+ occurrences.
- **Architecture**:
  1. **Focus Capture**: Uses Accessibility API (`AXUIElementCopyAttributeValue`) to capture focused element, PID, bundleID before paste.
  2. **Correction Session**: AXObserver-based session listens for `kAXValueChangedNotification` with idle-settle timer (800ms) and hard-stop (20s).
  3. **Diff Extraction**: Token-level prefix/suffix matching to extract replacement candidates.
  4. **Evidence Tracking**: Candidates tracked with count; promoted after threshold (2).
  5. **User Notification**: Shows "✅ Learned: 'X' → 'Y'" in transcript area on promotion.
- **Guardrails**:
  - Rejects full rewrites, punctuation-only changes, generic words.
  - Normalized edit distance threshold (≤0.7) prevents unrelated corrections.
- **Files**: `FocusCapture.swift`, `CorrectionSession.swift`, `CorrectionDiff.swift`, `LearnedDictionaryStore.swift`, `AppState.swift`

## Global Timeouts (10s Limit)

- **Issue**: Transcription/LLM could hang indefinitely on slow responses.
- **Fix**: Enforced 10-second timeout across all processing stacks:
  - Apple Speech: `DispatchWorkItem` timeout in `AppleSpeechEngine`.
  - Whisper: Async timeout wrapper.
  - LLM API: `URLRequest.timeoutInterval = 10`.
- **Files**: `SpeechTranscriber.swift`, `WhisperEngine.swift`, `LLMService.swift`

## Whisper Model Performance

- **Regression**: Switching from `.en.bin` (English-only) to `.bin` (multilingual) models caused ~3-5x slowdown.
- **Fix**: Always use English-only models (`ggml-base.en.bin`, `ggml-small.en.bin`, `ggml-medium.en.bin`) for fast transcription.
- **Files**: `AppState.swift` - `WhisperModel.filename` property.

## Silent Build Failures & Verification

- **Incident**: Tried to debug a UI issue by restarting the app multiple times, but changes weren't appearing.
- **Root Cause**: The `scripts/build_app.sh` script does not stop execution immediately upon a Swift compilation error if not strictly handled or monitored, or manual oversight missed the error log.
  - Specifically, a syntax error in `AppState.swift` (`init` method accidentally split, leaving valid code floating outside the class) caused the build to fail silently, so the "new" app bundle was never created. The user kept running the old binary.
- **Fix**:
  1. **Strict Error Checking**: Always check the exit code of build scripts.
  2. **Explicit Build Command**: Use `swift build -c release` directly when debugging compilation issues to see raw errors.
  3. **Code Repair**: Fixed the `init` structure and restored missing helper methods (`setupAudioMonitoring`, `updateHotKey`) and `processRecording` logic.
- **Lesson**: Never assume a build succeeded just because the script finished. Always verify the timestamp of the output bundle (`WisprClone.app`) or the exit code of the build command.

## Permission Regression Fix

- **Issue**: "Request Permissions" button became unresponsive after syntax repairs.
- **Root Cause**: The call to `appState.requestPermissions()` in `MenuBarView.swift` was commented out during a previous debugging session and not restored.
- **Fix**: Uncommented the line.
- **Lesson**: Leave TODO comments or use `#warning` when commenting out functional code to prevent accidental omission in production builds.

## Transcription Latency & Timeout Fix (2026-01-29)

- **Requirement**: End-to-end transcription must happen within **2 seconds**.
- **Issue**: Whisper inference was taking **28s+** for short clips, causing a "Whisper transcription timed out (10s)" error.
- **Root Cause**:
  1. **Low Thread Count**: Whisper was initialized with 4 threads, which was insufficient for fast local inference on some models.
  2. **Stale Binary**: The running binary had a 10s timeout, but the source code was out of sync (showing 60s).
- **Fixes**:
  1. **Thread Optimization**: Increased `params.n_threads` from 4 to **8** in `WhisperEngine.swift`.
  2. **Strict Timeout**: Reverted the source code to enforce a strict **10s timeout** per spec, ensuring the app "fails fast" if the requirement isn't met.
  3. **Build Sync**: Performed a clean rebuild using `scripts/build_app.sh` to sync the binary with the optimized source code.
- **Verification**: User confirmed permissions and app functionality restored.

## Paste Latency & UI Stalls Fix (2026-09-25)

- **Symptom**: Logs showed transcription (and "Total Pipeline") finishing immediately, but the text appeared near the cursor only after a noticeable delay, and the next hotkey press was sometimes ignored.
- **Root Causes**:
  1. **Focus capture blocked the paste**: `FocusCapture` (AX calls into the target app, including reading the whole field value) ran *before* `TextInjector.inject`. It was raced against a 200ms sleep in a `withThrowingTaskGroup`, but a task group always waits for every child, so the "timeout" never cut anything short. AX calls default to a ~6s messaging timeout each, and Electron/Chrome apps are slow to answer.
  2. **Main-thread AX in the correction session**: every value change in the target field triggered a synchronous AX read on the main thread for 3-20s after each paste, stalling the HUD and Carbon hotkey handling.
  3. **Busy status after paste**: status stayed `.pasting` for an extra 1s, and `startRecording` ignores the hotkey unless idle.
  4. **Same timeout bug in transcription**: Apple Speech/Whisper 30s timeouts were task groups too; a recognizer that never called back hung the app in `.transcribing`.
- **Fixes**:
  1. Paste first; capture focus and start the correction session afterwards on a background task.
  2. Global AX messaging timeout (0.5s) set at launch; correction-session reads moved to a serial background queue and coalesced.
  3. Status goes idle right after paste.
  4. `withTimeout` helper (`Timeout.swift`) that resumes at the deadline; Apple Speech now cancels the `SFSpeechRecognitionTask` and resumes its continuation exactly once.
  5. Smaller wins: HID key-release backup poll 100ms→30ms (debounce 300ms→90ms), HUD SwiftUI view built once instead of on every status change, mic level published at ~20 Hz via a separate `AudioLevelMeter` so only the waveform re-renders, clipboard restore made safe for back-to-back dictations.
